# StudyPulse

StudyPulse — offline-first учебный продукт для Android с Flask REST API.

Студент получает с сервера учебный пакет, скачивает его в приложение, планирует учебные слоты, повторяет карточки офлайн, а затем синхронизирует прогресс с сервером. Сервер начисляет XP, обновляет уровень, streak и недельный рейтинг.

## Главная идея

StudyPulse отвечает на два ключевых вопроса студента:

1. Что именно мне делать сегодня, чтобы всё успеть?
2. Где взять материал, чтобы это сделать?

Приложение связывает расписание, задания, учебные материалы, карточки, план слотов и прогресс в одном offline-first сценарии.

## Основной сценарий

1. Открыть приложение.
2. Зарегистрировать устройство на сервере.
3. Получить список учебных пакетов.
4. Скачать пакет в локальную базу Room.
5. Посмотреть расписание и задания.
6. Построить план учебных слотов.
7. Учиться офлайн: читать материалы и повторять карточки.
8. Синхронизировать прогресс.
9. Увидеть статистику и рейтинг.

### Блок 3. Room и offline-first хранение пакетов

Реализовано:
- локальная база Room;
- сущности учебных пакетов;
- сущности расписания;
- сущности заданий;
- сущности материалов;
- сущности карточек;
- скачивание bundle с сервера;
- сохранение пакета и связанных данных транзакцией;
- отображение статуса: не скачан / доступен офлайн.

После скачивания пакета приложение может работать без сервера.

### Блок 4. Расписание, задания и отмена занятия

Реализовано:
- экран Расписание;
- экран Задания;
- выборка данных только из скачанных пакетов;
- отмена конкретного занятия на дату;
- хранение отменённых занятий локально;
- отображение статуса задания;
- отображение дедлайна, приоритета и трудоёмкости.

Отменённое занятие учитывается планировщиком и не блокирует свободное окно.

### Блок 5. Планировщик учебных слотов

Реализовано:
- детерминированный планировщик;
- горизонт планирования: 3 дня;
- дневное окно: 08:00–22:00;
- минимальный слот: 30 минут;
- максимальная дневная нагрузка: 180 минут;
- учёт занятых интервалов из расписания;
- учёт отменённых занятий;
- сортировка заданий по дедлайну, приоритету и остатку;
- предпросмотр предложенного плана;
- принятие плана.

Планировщик объяснимый: пользователь видит, какие слоты предложены и почему.

### Блок 6. Материалы и интервальное повторение

Реализовано:
- экран Материалы;
- просмотр саммари материала;
- просмотр ключевых фактов;
- карточки для повторения;
- алгоритм SM-2;
- оценка карточки: Again / Hard / Good / Easy;
- локальный расчёт следующего повторения;
- лог повторений;
- локальная очередь событий.

Добавлен локальный mock Q&A:
- ответ формируется по сохранённому материалу;
- используется саммари и ключевые факты;
- внешний LLM не требуется;
- это демо-возможность для показа связки материал → вопрос → ответ.

### Блок 7. Выполнение учебных слотов

Реализовано:

- уменьшение remainingMinutes у задания;
- перевод задания в IN_PROGRESS;
- закрытие задания DONE при полном выполнении;
- создание событий SLOT_COMPLETED;
- создание события TASK_COMPLETED;
- запуск повторения карточек из слота;
- интеграция с локальной очередью синхронизации.

### Блок 8. Синхронизация прогресса

- обновление weekly_xp;
- обновление level;

- отметка synced после успешной синхронизации;
- обработка ошибок сети;

### Синхронизация

StudyPulse использует offline-first модель:

1. Все учебные данные хранятся локально в Room.
2. Пользовательские действия создают локальные события.
3. События хранятся с флагом synced = false.
4. При синхронизации события отправляются батчем на сервер.
5. Сервер проверяет client_event_id и не принимает дубликаты.
6. Сервер начисляет XP и обновляет прогресс.
7. Клиент помечает события как synced = true.

## Что не входит в текущий MVP

В текущий MVP не входят:

- настоящий OCR;
- настоящий ASR;
- настоящий RAG;
- векторный поиск;
- импорт произвольных PDF;
- облачные LLM в live-режиме;
- полноценная авторизация;
- роли преподавателя / студента / администратора;
- виджет;
- push-уведомления;
- SQLCipher;
- синхронизация между несколькими устройствами одного пользователя.
