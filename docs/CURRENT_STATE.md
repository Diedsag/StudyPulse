# StudyPulse: Текущее состояние репозитория

Этот документ фиксирует архитектуру и реализованный функционал на текущий момент (после завершения Фаз 2.1 – 2.5).

## 1. Общая архитектура
- **Подход:** Offline-first. Локальная база Room является единственным источником истины для учебных данных.
- **Backend:** Flask REST API (Python) используется для регистрации устройств, синхронизации прогресса (XP, streak, уровень) и раздачи демо-пакетов.
- **Стек Android:** Kotlin, Jetpack Compose, Material 3, Room, DataStore, Retrofit, OkHttp, WorkManager, Glance (виджеты).

## 2. Реализованные фазы

### Фаза 2.1: Локальные данные
- Сущности: `Subject`, `ScheduleTemplate`, `Task`, `Material`.
- Полный CRUD для предметов, расписания, заданий и материалов.
- Данные помечаются флагом `source` ("LOCAL" или "PACKAGE") для избежания конфликтов.

### Фаза 2.2: Экран "Сегодня" и управление планом
- Главный экран `TodayScreen`: приветствие, ближайший слот, срочные задания, карточки к повторению.
- Автоматическая пометка пропущенных слотов статусом `MISSED`.
- Кнопка "Перепланировать": очищает будущие `PLANNED` слоты и `MISSED`, перестраивая план с учетом актуального времени.
- Расчет риска просрочки (дефицит минут до дедлайна).
- Undo-действия (Snackbar с отменой) для удаления заданий и отмены занятий.

### Фаза 2.3: Чанки, цитаты и честный Q&A
- Сущность `MaterialChunkEntity` для хранения фрагментов текста.
- Автоматический чанкинг при создании/обновлении материала.
- `QaService`: поиск по ключевым словам в чанках, возврат ответа с цитатами и указанием источника.
- Режим "Ответить общо" с явным предупреждением, что ответ не основан на материалах.
- `MaterialRelevanceScorer`: алгоритм привязки релевантных материалов к учебному слоту на основе предмета, пакета и совпадения ключевых слов.

### Фаза 2.4: Уведомления, Виджет и Экспорт
- `NotificationWorker`: периодическая проверка (каждые 15 мин) предстоящих слотов и дедлайнов через WorkManager.
- `StudyPulseWidget`: Glance-виджет для главного экрана, показывающий ближайший слот и количество карточек.
- `PlanExporter`: экспорт локальных данных (предметы, расписание, задания, материалы) в JSON-формат для резервного копирования.

### Фаза 2.5: Полуручной импорт и Mock OCR
- `ScheduleParserService`: парсинг текста расписания (день, время, предмет, тип, аудитория, преподаватель) с оценкой уверенности (HIGH/MEDIUM/LOW).
- `ScheduleImportScreen`: предпросмотр распознанных занятий с возможностью ручной правки перед импортом.
- `MockOcrService`: имитация пайплайна OCR/ASR. Генерирует правдоподобное саммари и факты на основе ключевых слов в названии, демонстрируя UX без использования реальных LLM API.

## 3. Известные ограничения (Won't Have в MVP)
- Настоящий OCR рукописи или ASR аудио.
- Настоящий RAG с векторными эмбеддингами (используется keyword search).
- Облачные LLM в live-режиме.
- Полноценная авторизация и мультидевайс-синхронизация.
