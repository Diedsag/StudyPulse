# StudyPulse Phase 2 Plan

## Назначение документа

Этот документ описывает единый план развития StudyPulse после завершения MVP-блоков 0-10.

Фаза 2 нужна, чтобы превратить приложение из сильного учебного демо-стенда в самостоятельный студенческий ассистент, которым можно пользоваться ежедневно без обязательной зависимости от серверных учебных пакетов.

## Текущее состояние после Блока 10

Уже реализовано:

- Flask REST API.
- Регистрация устройства.
- Список учебных пакетов.
- Скачивание bundle пакета.
- Room offline-first хранилище.
- Расписание из пакетов.
- Задания из пакетов.
- Отмена занятия.
- Детерминированный планировщик учебных слотов.
- Материалы и карточки.
- Интервальное повторение SM-2.
- Фокус-таймер.
- Локальный mock Q&A.
- Синхронизация событий прогресса.
- Серверный XP, level, weekly XP, streak.
- Статистика и рейтинг.
- Русскоязычный UI и улучшенная тема.

## Главный продуктовый разрыв

Сейчас учебные данные в основном приходят с сервера как готовые пакеты.

Но исходная идея продукта предполагает, что студент может сам:

- создать предметы;
- внести расписание;
- добавить задания;
- добавить материалы;
- получить план на сегодня;
- увидеть риск просрочки;
- задать вопрос по своему материалу;
- получить ответ с цитатой;
- синхронизировать прогресс.

Поэтому Фаза 2 должна перевести приложение в модель:

    Локальные данные — primary source of truth
    Сервер — демо-контент, прогресс, XP, рейтинг, будущая обработка материалов

## Принципы Фазы 2

1. Не добавлять настоящий LLM, OCR, ASR и векторный поиск в ядро.
2. Сначала укрепить локальную модель данных.
3. Сделать приложение ежедневным через экран Сегодня.
4. Сделать планировщик живым: пропущенные слоты, перепланирование, риски.
5. Сделать Q&A честным через чанки и цитаты.
6. Показать путь к RAG и OCR через mock-сценарии, а не через внешние сервисы.
7. Улучшить UX через дизайн-систему, состояния, undo, доступность и локализацию.

### 2.1 Блок 11: локальные предметы, ручное расписание и задания

Цель:

- сделать приложение пригодным для жизни без backend-пакетов.

Что добавляем:

- Subject;
- ScheduleTemplate;
- расширенный ClassInstance;
- ручной Task;
- ручной Material;
- поле source: LOCAL или PACKAGE;
- CRUD UI для предметов, расписания, заданий и материалов.

Критерии готовности:

- пользователь может создать предмет без сервера;
- пользователь может добавить занятие вручную;
- пользователь может добавить задание вручную;
- пользователь может добавить материал вручную;
- ручные данные хранятся в Room;
- пакеты с сервера не ломают ручные данные;
- расписание можно редактировать и удалять;
- задания можно создавать с дедлайном и трудоёмкостью;
- приложение работает полностью офлайн.

### 2.2 Блок 12: экран Сегодня, перепланирование и риски

Цель:

- сделать StudyPulse ежедневным инструментом.

Что добавляем:

- главный экран Сегодня;
- статус MISSED для пропущенных слотов;
- кнопку Перепланировать;
- расчёт риска просрочки;
- undo через snackbar;
- быстрые действия: добавить задание, занятие, материал.

Критерии готовности:

- есть экран Сегодня;
- на нём виден ближайший слот;
- видны срочные задания;
- видны карточки к повторению;
- пропущенные слоты получают статус MISSED;
- есть кнопка Перепланировать;
- планировщик показывает дефицит времени до дедлайна;
- пользователь понимает, почему предложен именно этот слот;
- есть undo для опасных действий.

### 2.3 Блок 13: чанки, цитаты и честный Q&A

Цель:

- сделать mock Q&A объяснимым и близким к будущему RAG.

Что добавляем:

- MaterialChunk;
- поиск по чанкам;
- цитаты;
- источник: страница или таймкод;
- честный ответ, если информации нет;
- отдельный режим Ответить общо;
- релевантную связку слот и материал.

Критерии готовности:

- материал разбивается на чанки;
- Q&A ищет по чанкам;
- ответ содержит цитату;
- указан источник;
- если ответа нет, приложение честно говорит об этом;
- слот показывает релевантные материалы;
- из слота можно перейти в саммари и Q&A.

### 2.4 Блок 14: уведомления, виджет и экспорт

Цель:

- сделать приложение заметным в ежедневной рутине.

Что добавляем:

- уведомления за 15 минут до слота;
- уведомления за 24 часа до дедлайна;
- уведомления о карточках к повторению;
- виджет через Glance;
- экспорт плана в JSON;
- импорт JSON в dry-run режиме.

Критерии готовности:

- есть уведомление за 15 минут до слота;
- есть уведомление о дедлайне;
- есть виджет с ближайшим слотом;
- можно экспортировать план в JSON;
- можно импортировать JSON хотя бы в dry-run режиме;
- настройки позволяют отключить уведомления.

### 2.5 Блок 15: полуручной импорт расписания и mock OCR

Цель:

- показать путь к реальной автоматизации без настоящего OCR и LLM.

Что добавляем:

- вставку текста расписания;
- парсинг базовых полей;
- предпросмотр распознанных занятий;
- ручную правку;
- mock OCR экран для материала;
- имитацию обработки фото в саммари, факты и карточки.

Критерии готовности:

- можно вставить текст расписания;
- приложение парсит базовые поля;
- есть экран предпросмотра;
- можно исправить распознанные поля;
- mock OCR показывает процесс обработки материала;
- после mock-обработки появляется материал с саммари и карточками.

### 2.6 Блок 16: дизайн-система, доступность, локализация, тесты

Цель:

- сделать продукт аккуратным и защищаемым.

Что добавляем:

- полноценный MaterialTheme;
- светлую и тёмную палитру;
- переключатель dynamic color;
- дизайн-компоненты;
- единые empty/error/loading states;
- строки в resources;
- базовые unit-тесты планировщика;
- базовые Room DAO тесты.

Критерии готовности:

- есть единая тема Material 3;
- есть светлая и тёмная палитра;
- есть переключатель dynamic color;
- есть дизайн-компоненты;
- все экраны имеют loading, empty, error, content;
- строки вынесены в resources;
- есть базовые unit-тесты планировщика;
- есть базовые тесты Room DAO.

## Что не делаем в Фазе 2

В Фазе 2 сознательно не делаем:

- настоящий OCR рукописи;
- настоящий ASR;
- векторный поиск;
- эмбеддинги;
- SQLCipher;
- облачные LLM в live demo;
- сложные роли;
- групповой шеринг;
- автоизвлечение заданий;
- полноценный AI-чат;
- мультидевайс синхронизацию.
