# StudyPulse: Фаза 3.7 release checklist

## Цель

Подготовить приложение к демонстрации и установке как debug APK.

## 1. Проверка репозитория

Выполни:

git status --short
git log --oneline -20
git branch --show-current

Ожидаемо:

- рабочая ветка phase3-dev;
- нет непреднамеренных изменений;
- последние коммиты соответствуют Фазам 3.5, 3.6 и 3.7.

## 2. Сборка

В Android Studio:

File -> Sync Project with Gradle Files
Build -> Clean Project
Build -> Rebuild Project

Через PowerShell:

Set-Location -LiteralPath 'C:\Users\lelec\AndroidStudioProjects\StudyPulse\StudyPulse\android'
.\gradlew.bat :app:assembleDebug

Ожидаемый APK:

android\app\build\outputs\apk\debug\app-debug.apk

## 3. Установка на устройство

Подключи телефон с USB-отладкой.

Проверка:

adb devices

Установка:

adb install -r "C:\Users\lelec\AndroidStudioProjects\StudyPulse\StudyPulse\android\app\build\outputs\apk\debug\app-debug.apk"

Если есть конфликт подписи:

adb uninstall com.studypulse.sync
adb install "C:\Users\lelec\AndroidStudioProjects\StudyPulse\StudyPulse\android\app\build\outputs\apk\debug\app-debug.apk"

## 4. Проверка онбординга

Очисти данные приложения:

adb shell pm clear com.studypulse.sync

Запусти приложение.

Проверь:

- появляется онбординг;
- можно ввести имя;
- можно выбрать время учёбы;
- можно включить уведомления;
- можно завершить настройку;
- после завершения открывается главный экран;
- при повторном запуске онбординг не показывается.

## 5. Проверка автоплана

Включи автоплан.

Добавь хотя бы одно активное задание.

Перезапусти приложение.

Проверь:

- план появляется автоматически;
- на экране "Сегодня" есть ближайший слот или осмысленное пустое состояние;
- ручные кнопки не являются обязательными для базового сценария.

## 6. Проверка напоминаний

В настройках включи:

- напоминания;
- учебные слоты;
- дедлайны;
- утренний дайджест.

Проверь:

- приложение не падает;
- каналы уведомлений создаются;
- тихие часы работают как переключатель;
- напоминания планируются без явных крашей.

Для точной проверки уведомления лучше использовать слот через 15-20 минут и дедлайн на завтра.

## 7. Проверка backup

Открой Настройки -> Резервная копия.

Проверь:

- кнопка "Создать резервную копию" работает;
- появляется файл в списке;
- кнопка "Восстановить" показывает подтверждение;
- кнопка "Удалить" удаляет копию.

## 8. Проверка синхронизации

Если backend запущен:

- приложение не должно падать;
- статус синхронизации должен быть мягким;
- server URL и device UID не должны быть на главном экране.

Если backend выключен:

- приложение должно работать офлайн;
- ошибка сети не должна ломать основной UI.

## 9. Проверка виджета

Добавь виджет StudyPulse на главный экран.

Проверь:

- виджет показывает дату и ближайший слот;
- клик по виджету открывает приложение;
- после изменения плана виджет обновляется через WorkManager.

## 10. Документация

Проверь, что README и docs не противоречат коду.

Особенно важно:

- виджет реализован;
- локальные уведомления реализованы;
- mock OCR существует как демо-функция;
- настоящий OCR/ASR/RAG не реализованы.

## 11. Демо-сценарий

Короткий сценарий для показа:

1. Установлен debug APK.
2. Показан онбординг.
3. Создано задание.
4. Приложение автоматически построило план.
5. Показан экран "Сегодня".
6. Показаны настройки с человеческим UI.
7. Показан backup.
8. Показан виджет.
9. Показана статистика/синхронизация, если backend запущен.

## 12. Критерий готовности Фазы 3.7

Фаза 3.7 считается выполненной, если:

- приложение собирается;
- debug APK устанавливается;
- онбординг проходит без краша;
- автоплан работает;
- настройки не показывают технические термины обычному пользователю;
- backup создаётся;
- виджет работает;
- документация актуальна.
