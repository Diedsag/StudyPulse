# StudyPulse — Phase 4 release notes

Фаза 4 была посвящена не новым фичам, а приведению продукта в рабочее состояние: исправление UX, layout, Q&A, статистики, настроек и резервных копий.

---

## 1. Главные итоги

```text
Продукт собран.
Debug APK работает.
Ручные тесты пройдены.
Основные жалобы пользователя закрыты.
Документация обновлена.
Можно передавать сокоманднику.
```

---

## 2. Исправлено по экранам

### Статистика

Было:

```text
рейтинг загружался только по кнопке Обновить;
недельный рейтинг мог обновляться, а рейтинг за всё время оставался старым.
```

Стало:

```text
при открытии экрана и при resume автоматически обновляются оба периода: week и all;
кнопка Обновить осталась как ручная страховка.
```

Ключевые файлы:

```text
StatsViewModel.kt
StatsScreen.kt
```

---

### Q&A

Было:

```text
локальные материалы не чанковались автоматически;
поиск использовал только первое ключевое слово;
регистр кириллицы мог резать recall;
экран мог выглядеть молча сломанным.
```

Стало:

```text
QaViewModel.start() автоматически вызывает chunkMaterial(material);
QaService.askQuestion() перебирает все ключевые слова и весь вопрос как fallback;
поиск пробует варианты регистра;
добавлены понятные состояния: загрузка, ошибка, ответ не найден;
добавлен поясняющий блок, что это демо-поиск, а не настоящий RAG.
```

Ключевые файлы:

```text
QaService.kt
QaViewModel.kt
QaScreen.kt
```

---

### Материалы

Было:

```text
форму добавления нельзя было нормально закрыть;
не было видно, какой предмет выбран;
сохранённый текст мог не отображаться;
экран не скроллился нормально;
пустое название могло сохраняться.
```

Стало:

```text
корневой Column скроллится;
форма закрывается кнопками Скрыть и Скрыть форму;
выбранный предмет подсвечивается и подписывается;
карточка материала показывает rawText, если он непустой, иначе summaryText;
добавлен guard: пустое название не сохраняется;
добавлена базовая accessibility-семантика.
```

Ключевые файлы:

```text
MaterialsScreen.kt
MaterialsViewModel.kt
```

### Расписание

Было:

```text
дни недели и кнопки сжимались/наладались;
форму было трудно закрыть;
кнопки карточки могли вылеза за экран;
занятия отсортированы по порядку добавления.

кнопки Отменить/Редактировать/Удалить переносятся корректно;
занятия сортируются по дате и времени начала.
```

Ключевые файлы:

```text
ScheduleScreen.kt
ScheduleViewModel.kt
```

### Настройки и backup

Было:

```text
создание резервной копии крашило приложение;
повторный вход в настройки тоже крашился;
в тихих часах кнопка + для До уходила за правый край.

тихие часы переверстаны вертикально;
кнопки + и - для С и До видны на узких экранах.
```

Ключевые файлы:

```text
SettingsScreen.kt
```

## 3. Что осталось демо-ограничением

```text
Q&A — keyword search, не RAG.
OCR — placeholder, не реальное распознавание.
Push-уведомления — не серверные, только локальные Android notifications.
Нет аккаунтов.
Нет мультидевайс.
```

Это не баги Фазы 4, а осознанные границы MVP/демо.

---

## 4. Итог Фазы 4

Фаза 4 закрыла главный риск проекта: продукт перестал выглядеть поломанным в ручных сценариях. Теперь можно показывать учебный цикл целиком и честно объяснять, какие части являются демо.
