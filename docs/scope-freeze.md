# StudyPulse Scope Freeze

## Формула MVP

StudyPulse MVP — это Android-приложение + Flask API, где студент может:

1. зарегистрировать устройство;
2. получить список учебных пакетов;
3. скачать пакет локально;
4. увидеть расписание, задания, материалы и карточки;
5. построить план учебных слотов;
6. пройти повторение карточек офлайн;
7. отметить выполнение слота;
8. синхронизировать локальные события с сервером;
9. увидеть статистику, XP, уровень, streak и недельный рейтинг.

## Must Have — обязательно

### Android

1. Хранение настроек в DataStore:
   - server URL;
   - device_uid;
   - nickname;
   - last sync timestamp;
   - rating opt-in.

2. Генерация device_uid при первом запуске.

3. Экран настроек / подключения:
   - поле server URL;
   - отображение device_uid;
   - кнопка «Проверить соединение»;
   - статус: Connected / Offline / Error.

4. Регистрация устройства на сервере:
   - POST /api/devices/register.

5. Список учебных пакетов с сервера:
   - GET /api/packages.

6. Скачивание учебного пакета:
   - GET /api/packages/{external_id}/bundle;
   - сохранение в Room одной транзакцией.

7. Локальное хранение в Room:
   - packages;
   - schedule items;
   - class instances / cancellations;
   - tasks;
   - materials;
   - cards;
   - review logs;
   - pending events;
   - user stats cache;
   - leaderboard cache.

8. Экран «Пакеты»:
   - список пакетов;
   - статус: не скачан / скачан / обновлён;
   - кнопка «Скачать» / «Обновить».

9. Экран «Расписание»:
   - занятия из скачанного пакета;
   - простой вид на несколько дней;
   - возможность отменить занятие.

10. Экран «Задания»:
   - список задач;
   - дедлайн;
   - трудоёмкость;
   - приоритет;
   - статус.

11. Планировщик учебных слотов:
   - горизонт: сегодня + 2 дня;
   - дневное окно: 08:00–22:00;
   - минимальный слот: 30 минут;
   - максимальная дневная учебная нагрузка: 180 минут;
   - учёт занятых интервалов из расписания;
   - учёт отменённых занятий;
   - сортировка задач по дедлайну, приоритету и остатку трудоёмкости;
   - генерация предложенных слотов;
   - предпросмотр плана;
   - принятие плана.

12. Учебный слот:
   - привязка к задаче;
   - привязка к материалу, если есть;
   - кнопка «Повторить карточки»;
   - кнопка «Отметить выполненным».

13. Интервальное повторение:
   - показ front;
   - показ back;
   - оценки:
     - Again;
     - Hard;
     - Good;
     - Easy;
   - пересчёт dueAt;
   - сохранение review log;
   - создание pending event.

14. Очередь синхронизации:
   - локальные события со статусом synced=false;
   - кнопка «Синхронизировать»;
   - отправка батчем на сервер;
   - после успеха помечать synced=true;
   - при ошибке оставлять в очереди.

15. Статистика:
   - pending events count;
   - last sync time;
   - total XP;
   - weekly XP;
   - level;
   - streak;
   - reviews today;
   - completed slots.

16. Рейтинг:
   - недельный leaderboard;
   - top 10;
   - своё место;
   - локальный кэш.

### Backend Flask

1. GET /health.

2. POST /api/devices/register.

3. GET /api/packages.

4. GET /api/packages/{external_id}/bundle.

5. POST /api/sync/batch.

6. GET /api/me/stats.

7. GET /api/leaderboard.

8. SQLAlchemy models:
   - Device;
   - StudyPackage;
   - PackageScheduleItem;
   - PackageTask;
   - PackageMaterial;
   - PackageCard;
   - SyncEvent.

9. SQLite база для демо.

10. Seed-данные:
   - 2–3 учебных пакета;
   - расписание;
   - задания;
   - материалы;
   - карточки;
   - 3–5 устройств для рейтинга;
   - немного истории событий, чтобы рейтинг не был пустым.

11. Серверный расчёт XP, уровня, streak и leaderboard.

12. Идемпотентность событий через client_event_id.

## Ограничение по сложности планировщика

Планировщик в MVP не должен быть идеальным оптимизатором.

Допустимо:

- рассматривать только ближайшие 3 дня;
- использовать фиксированные временные окна;
- не учитывать праздники;
- не учитывать часовой пояс пользователя, кроме локального времени устройства;
- не делать drag-and-drop редактирование слотов;
- не делать частичное выполнение задачи внутри нескольких слотов сложнее, чем уменьшение remainingMinutes.

Главное: планировщик должен быть детерминированным и объяснимым.

## Ограничение по AI-части

В MVP нет настоящего AI.

Есть:

- материалы с заранее подготовленным summary;
- key facts;
- карточки;
- mock Q&A или простой keyword search.

Интерфейс AiGateway можно заложить архитектурно, но реализация — mock.

## Ограничение по рейтингу

Рейтинг — Rating Lite:

- XP;
- level;
- streak;
- weekly leaderboard.

Нет:

- друзей;
- групп;
- аватарок;
- реальных имён;
- сложных лиг;
- сезонных наград.

## Определение готовности MVP

MVP считается готовым, если выполняется главный сценарий:

1. Приложение запускается.
2. Подключается к локальному Flask-серверу.
3. Регистрирует устройство.
4. Показывает список пакетов.
5. Скачивает пакет.
6. Показывает расписание, задания, материалы и карточки.
7. Генерирует план слотов.
8. Позволяет пройти повторение офлайн.
9. Сохраняет события локально.
10. Синхронизирует события на сервер.
11. Показывает обновлённую статистику и рейтинг.
12. Не падает при отсутствии интернета, пустых данных и повторной синхронизации.
