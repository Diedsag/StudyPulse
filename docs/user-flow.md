# StudyPulse User Flow

## Главный happy path

1. Пользователь устанавливает и запускает StudyPulse.
2. Приложение генерирует device_uid и сохраняет его в DataStore.
3. Пользователь попадает на экран настроек или сразу видит статус подключения.
4. Приложение пытается зарегистрировать устройство на сервере:
   - POST /api/devices/register.
5. Если сервер доступен, приложение получает список учебных пакетов:
   - GET /api/packages.
6. Пользователь видит пакеты:
   - «Физика: Лекция 5 и лабораторная»;
   - «История: Билеты 1–10».
7. Пользователь нажимает «Скачать пакет».
8. Приложение запрашивает bundle:
   - GET /api/packages/{external_id}/bundle.
9. Приложение сохраняет в Room:
   - пакет;
   - расписание;
   - задания;
   - материалы;
   - карточки.
10. Пользователь открывает скачанный пакет.
11. Видит:
   - расписание;
   - задания;
   - материалы;
   - карточки;
   - кнопку «Спланировать».
12. Нажимает «Спланировать».
13. Планировщик:
   - берёт занятые интервалы из расписания;
   - исключает отменённые занятия;
   - находит свободные окна;
   - распределяет задачи по дедлайнам и приоритетам.
14. Пользователь видит предпросмотр плана.
15. Нажимает «Принять план».
16. Приложение создаёт StudySlot со статусом PLANNED.
17. Создаёт локальное событие PLAN_ACCEPTED.
18. Пользователь открывает учебный слот.
19. Внутри слота видит:
   - задачу;
   - материал;
   - карточки к повторению;
   - кнопку «Отметить выполненным».
20. Пользователь нажимает «Повторить карточки».
21. Приложение показывает due cards.
22. Пользователь смотрит вопрос, показывает ответ, оценивает:
   - Again;
   - Hard;
   - Good;
   - Easy.
23. Приложение обновляет card.dueAt.
24. Приложение сохраняет ReviewLog.
25. Приложение создаёт PendingEvent CARD_REVIEWED.
26. Пользователь возвращается в слот и нажимает «Отметить выполненным».
27. Приложение меняет статус слота на DONE.
28. Приложение создаёт PendingEvent SLOT_COMPLETED.
29. Пользователь нажимает «Синхронизировать».
30. Приложение отправляет все unsynced events:
   - POST /api/sync/batch.
31. Сервер принимает события, начисляет XP, обновляет level/streak.
32. Приложение получает обновлённую статистику:
   - GET /api/me/stats.
33. Приложение получает рейтинг:
   - GET /api/leaderboard.
34. Пользователь видит:
   - XP;
   - уровень;
   - streak;
   - своё место в недельном рейтинге.

## Сценарий «препод заболел»

1. Пользователь открывает расписание.
2. Выбирает занятие.
3. Нажимает «Отменить».
4. Приложение создаёт или обновляет ClassInstance со статусом CANCELLED.
5. Занятие перестаёт считаться занятым интервалом.
6. Пользователь нажимает «Перепланировать».
7. Планировщик использует освободившееся окно.
8. Создаётся событие CLASS_CANCELLED.

## Offline-сценарий

1. Интернет отсутствует.
2. Пользователь открывает приложение.
3. Приложение не может получить новые пакеты.
4. Показывает кэш из Room.
5. Статус: Offline.
6. Пользователь может:
   - открыть скачанный пакет;
   - посмотреть расписание;
   - посмотреть задания;
   - построить план локально;
   - повторить карточки;
   - отметить слот выполненным.
7. Все действия создают PendingEvent со synced=false.
8. При появлении интернета пользователь нажимает «Синхронизировать».
9. Приложение отправляет накопленные события.

## Сценарий ошибки сети

1. Пользователь нажимает «Синхронизировать».
2. Сервер недоступен.
3. Приложение показывает ошибку.
4. События остаются synced=false.
5. Счётчик pending events не уменьшается.
6. Пользователь может повторить попытку позже.

## Сценарий повторной синхронизации

1. Приложение отправило события.
2. Сервер принял их, но ответ потерялся или приложение упало до пометки synced=true.
3. При следующем sync клиент снова отправляет те же client_event_id.
4. Сервер видит дубликаты и не начисляет XP повторно.
5. Сервер возвращает duplicated count.
6. Клиент помечает события synced=true.

## Empty states

Приложение не должно падать, если:

- нет интернета;
- сервер вернул пустой список пакетов;
- пакет не скачан;
- в пакете нет карточек;
- в пакете нет заданий;
- нет due cards;
- нет pending events;
- рейтинг пустой;
- статистика ещё не синхронизирована.
